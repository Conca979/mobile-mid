## 2. Lecture 2 Technical Foundation & Environment Configuration

### 2.1 Git Version Control Architecture (`.gitignore`)
In professional Android development (evaluated in MCQ `L1-Q22`), developers must separate human-authored source assets from machine-specific IDE metadata and transient compiler caches.

```text
# Root .gitignore for USTH Weather
.gradle/
build/
app/build/
.idea/
local.properties
*.iml
.DS_Store
/captures
```

#### Line-by-Line Breakdown:
- `.gradle/`: Internal execution caches generated by the Gradle build daemon. Tracking this corrupts cross-workstation builds.
- `build/` and `app/build/`: Output directories where `javac`, `dx` / `d8`, and `aapt` place compiled `.class`, `.dex`, and intermediate APK outputs. Tracking binary build outputs causes merge conflicts.
- `.idea/` and `*.iml`: JetBrains Android Studio IDE workspace configuration files containing absolute file paths specific to a single operating system.
- `local.properties`: Contains the absolute filesystem path to the host machine's Android SDK (`sdk.dir=/Users/...` or `C:\\Users\\...`). Committing this breaks compilation on other workstations.
- `src/` and `build.gradle` (tracked): All Java source code, XML layouts, and Gradle dependency declarations remain strictly tracked to ensure reproducibility.

### 2.2 Host Architecture & Emulation vs. Hardware Debugging
- **Workstation Bottleneck (`L1-Q16`, `L1-Q18`):** Running an x86/ARM emulator alongside Android Studio on a dual-core host with 4GB of physical RAM forces intense virtual memory disk paging (thrashing). Connecting a physical Android device via USB debugging offloads execution, CPU scheduling, and RAM heap allocations to the smartphone hardware, freeing workstation memory.
- **ISA ABI Heterogeneity (`L1-Q04`):** Compiling native C/C++ libraries (`.so`) exclusively for 32-bit ARMv7 triggers an `UnsatisfiedLinkError` on x86 emulators unless binary translation layers or multi-ABI packaging (`arm64-v8a`, `x86_64`) are declared in `build.gradle`.

### 3.2 Exhaustive Line-by-Line Breakdown:
- **Line 1: `<?xml version="1.0" encoding="utf-8"?>`**  
  Standard XML processing instruction declaring XML version 1.0 and UTF-8 character encoding, preventing multi-byte corruption during AAPT compilation.
- **Line 2: `<manifest xmlns:android="http://schemas.android.com/apk/res/android"`**  
  Declares the root schema for Android's package metadata. The XML namespace URI `xmlns:android` binds the `android:` prefix to Android's platform attributes (`L3-Q02`).
- **Line 3: `package="vn.edu.usth.weather">`**  
  Defines the unique application ID and default Java namespace. At install time, the Linux kernel assigns a distinct Linux User ID (`UID`) to this package, establishing an isolated sandbox (`L2-Q06`).
- **Line 5: `<application`**  
  The parent container configuring global process-level parameters for the app.
- **Line 6: `android:allowBackup="true"`**  
  Enables the system to include app data in cloud and ADB backup archives.
- **Line 7: `android:icon="@mipmap/ic_launcher"`**  
  References the application's launcher icon in `res/mipmap/`. Mipmaps are used for launcher icons because they are retained across density buckets without downsampling.
- **Line 8: `android:label="@string/app_name"`**  
  Resolves the human-readable application title from `res/values/strings.xml`, adhering to resource externalization rules (`L3-Q01`).
- **Line 9: `android:roundIcon="@mipmap/ic_launcher_round"`**  
  Supplies a circular icon asset for modern launchers (Android 7.1+).
- **Line 10: `android:supportsRtl="true"`**  
  Enables bidirectional layout mirroring for right-to-left scripts (Arabic, Hebrew).
- **Line 11: `android:theme="@style/AppTheme">`**  
  Applies the base window appearance and color palette defined in `res/values/styles.xml`.
- **Line 13: `<activity`**  
  Registers `WeatherActivity` with the system's `ActivityManagerService`. Any Activity launched without registration throws an `ActivityNotFoundException` (`L2-Q11`).
- **Line 14: `android:name=".WeatherActivity"`**  
  Relative class shorthand, expanding to `vn.edu.usth.weather.WeatherActivity`.
- **Line 15: `android:exported="true">`**  
  Mandatory declaration (Android 12+) permitting external components (the OS Home launcher) to instantiate this Activity.
- **Line 16: `<intent-filter>`**  
  Declares capabilities and intent matching criteria for this component.
- **Line 17: `<action android:name="android.intent.action.MAIN" />`**  
  Declares this Activity as the primary entry point of the package requiring no input data (`L2-Q12`).
- **Line 18: `<category android:name="android.intent.category.LAUNCHER" />`**  
  Instructs the system launcher to display an icon for this Activity in the app drawer. Without this tag, the app installs onto the device but has no launcher icon (`L2-Q12`).

```java
import androidx.appcompat.app.AppCompatActivity;

public class WeatherActivity extends AppCompatActivity {

  protected void onDestroy() {

  }

```

### 4.2 Exhaustive Line-by-Line Breakdown:
- **Line 1: `package vn.edu.usth.weather;`**  
  Declares the package identifier matching the namespace in `AndroidManifest.xml`.
- **Line 3: `import android.os.Bundle;`**  
  Imports the key-value mapping class passed during lifecycle recreation to restore transient state (`L2-Q17`).
- **Line 4: `import android.util.Log;`**  
  Imports Android's logging utility that routes output to the kernel `logcat` circular ring buffer (`L2-Q14`).
- **Line 5: `import androidx.appcompat.app.AppCompatActivity;`**  
  Imports the backward-compatible Activity class from Jetpack (Support Library), enabling Material Design themes and Action Bar support on older Android versions.
- **Line 7: `public class WeatherActivity extends AppCompatActivity {`**  
  Declares `WeatherActivity` inheriting all lifecycle dispatch logic from `AppCompatActivity` and `Context` (`L2-Q10`).
- **Line 8: `private static final String TAG = "WeatherActivity";`**  
  Defines a static constant tag (max 23 characters on legacy platforms) used to filter messages in the Logcat window.
- **Line 10: `@Override`**  
  Compiler annotation enforcing that the method signature exactly overrides a superclass callback, avoiding silent spelling mismatches.
- **Line 11: `protected void onCreate(Bundle savedInstanceState) {`**  
  First lifecycle callback executed when the OS process instantiates the Activity. `savedInstanceState` is null on cold launch, or contains serialized data if recreated following screen rotation (`L2-Q17`).
- **Line 12: `super.onCreate(savedInstanceState);`**  
  **Mandatory line.** Calling the superclass method restores internal state and fragment managers. Omitting this call throws a `SuperNotCalledException` at runtime (`L2-Q15`).
- **Line 13: `setContentView(R.layout.activity_weather);`**  
  Instructs the `LayoutInflater` to parse `res/layout/activity_weather.xml`, instantiate all declared `View` objects into memory, and attach them to the window's decor view (`L3-Q05`).
- **Line 14: `Log.i(TAG, "onCreate: Activity initialized and view inflated.");`**  
  Writes an informational (`Log.i`) log message. Tracing proves that the initialization phase completed successfully.
- **Line 17–20: `onStart()` callback**  
  Triggered when the Activity becomes visible on screen. `super.onStart()` must be called first.
- **Line 23–26: `onResume()` callback**  
  Triggered when the Activity enters the top of the ActivityManager back stack and begins receiving user touch/key events. Ideal location to re-acquire exclusive hardware (Camera, GPS listeners) (`L2-Q16`).
- **Line 29–32: `onPause()` callback**  
  Triggered when an incoming dialogue, notification shade, or split-screen partially obscures the Activity. `super.onPause()` must be called. Heavy computations must be halted here, and camera sensors released to avoid locking hardware (`L2-Q16`).
- **Line 35–38: `onStop()` callback**  
  Triggered when the Activity is completely hidden from the user.
- **Line 41–44: `onDestroy()` callback**  
  Final callback executed when the Activity is popped off the back stack (user presses Back) or `finish()` is explicitly invoked (`L2-Q18`).

### 4.3 Practical Lifecycle Verification & Traps:
- **Device Rotation (`L2-Q17`):** Rotating the phone from portrait to landscape triggers the complete destruction and immediate re-creation sequence:
  ```text
  onPause() -> onStop() -> onDestroy() -> onCreate() -> onStart() -> onResume()
  ```
- **Home Button Press vs. Back Button Press (`L2-Q18`):**
  - Tapping **Home**: Triggers `onPause() -> onStop()`. The instance remains cached in RAM.
  - Tapping **Back**: Pops the Activity from the back stack, invoking `onPause() -> onStop() -> onDestroy()`.

**Lecture Reference:** Lecture 3, Slides 38–52

### 5.1 `app/src/main/java/vn/edu/usth/weather/ForecastFragment.java`
```java
package vn.edu.usth.weather;

import android.graphics.Color;
import android.os.Bundle;
import android.view.LayoutInflater;
import android.view.View;
import android.view.ViewGroup;
import androidx.annotation.NonNull;
import androidx.annotation.Nullable;
import androidx.fragment.app.Fragment;

public class ForecastFragment extends Fragment {

  public ForecastFragment() {
    // Required empty public constructor for FragmentManager instantiation
  }

  @Nullable
  @Override
  public View onCreateView(@NonNull LayoutInflater inflater,
                           @Nullable ViewGroup container,
                           @Nullable Bundle savedInstanceState) {
    // Instantiate an empty View programmatically
    View view = new View(getContext());
    
    // Set translucent reddish background (#20FF0000: Alpha 0x20 = ~12.5% opacity)
    view.setBackgroundColor(Color.parseColor("#20FF0000"));
    
    return view;
  }
}
```

```java
    super.onCreate(savedInstanceState);

    if (savedInstanceState == null) {
```

### 5.4 Exhaustive Line-by-Line Breakdown:
- **`public ForecastFragment() {}`**  
  Android requires every `Fragment` subclass to provide a parameterless public constructor. When the OS re-creates fragments following configuration changes (e.g. rotation), the internal reflection engine calls this default constructor. Passing arguments via custom constructors causes runtime crashes (`L2-Q22`).
- **`onCreateView(@NonNull LayoutInflater inflater, ...)`**  
  Lifecycle hook responsible for creating and returning the Fragment's UI hierarchy.
- **`View view = new View(getContext());`**  
  Constructs a bare `View` instance using the hosting Activity context (`L2-Q10`).
- **`view.setBackgroundColor(Color.parseColor("#20FF0000"));`**  
  Parses a 32-bit ARGB hex color string. `#20` represents alpha (transparency: `0x20 / 0xFF` = 12.5%), `#FF` is red, `#00` green, `#00` blue. This visual tint confirms the fragment's bounds without blocking underlying containers.
- **`if (savedInstanceState == null)`**  
  **CRITICAL ARCHITECTURAL CHECK (`L2-Q24`).** If the Activity is recreating after screen rotation, the `FragmentManager` automatically restores the previously existing fragment from the saved bundle. Re-adding it unconditionally on every `onCreate()` causes duplicate overlapping fragments in memory.
- **`getSupportFragmentManager().beginTransaction()`**  
  Spawns an atomic `FragmentTransaction`. Changes (add, remove, replace) are batched together.
- **`.add(R.id.container, forecastFragment)`**  
  Attaches `forecastFragment` to the `FrameLayout` with ID `R.id.container`.
- **`.commit();`**  
  Schedules the transaction onto the main application thread's event loop.

## 6. Practical Work 4: Programmatic View Hierarchy Construction
**Lecture Reference:** Lecture 3, Slides 53–65  
**MCQ Alignment:** `L2-Q26`, `L2-Q27`, `L2-Q28`, `L2-Q29`, `L2-Q30`, `L2-Q31`, `L2-Q32`

### 6.1 Programmatic `ForecastFragment.java`
```java
package vn.edu.usth.weather;

import android.graphics.Color;
import android.os.Bundle;
import android.view.Gravity;
import android.view.LayoutInflater;
import android.view.View;
import android.view.ViewGroup;
import android.widget.ImageView;
import android.widget.LinearLayout;
import android.widget.TextView;
import androidx.annotation.NonNull;
import androidx.annotation.Nullable;
import androidx.fragment.app.Fragment;

public class ForecastFragment extends Fragment {

  public ForecastFragment() {}

  @Nullable
  @Override
  public View onCreateView(@NonNull LayoutInflater inflater,
                           @Nullable ViewGroup container,
                           @Nullable Bundle savedInstanceState) {
    // 1. Create the parent container ViewGroup
    LinearLayout layout = new LinearLayout(getContext());
    layout.setOrientation(LinearLayout.VERTICAL);
    layout.setLayoutParams(new LinearLayout.LayoutParams(
      LinearLayout.LayoutParams.MATCH_PARENT,
      LinearLayout.LayoutParams.MATCH_PARENT
    ));
    layout.setGravity(Gravity.CENTER_HORIZONTAL);
    layout.setBackgroundColor(Color.parseColor("#200000FF")); // Translucent Blue

    // 2. Create the child TextView
    TextView dayTextView = new TextView(getContext());
    dayTextView.setText("Thursday");
    dayTextView.setTextSize(20f);
    dayTextView.setTextColor(Color.BLACK);
    dayTextView.setPadding(0, 16, 0, 8);

    // 3. Create the child ImageView
    ImageView weatherIcon = new ImageView(getContext());
    // Resource drawable identifier generated into R.java by AAPT
    weatherIcon.setImageResource(R.drawable.weather_sunny);
    weatherIcon.setLayoutParams(new LinearLayout.LayoutParams(
      200, // width in pixels
      200  // height in pixels
    ));

    // 4. Assemble the view tree
    layout.addView(dayTextView);
    layout.addView(weatherIcon);

    return layout;
  }
}
```

### 6.2 Exhaustive Line-by-Line Breakdown:
- **`LinearLayout layout = new LinearLayout(getContext());`**  
  Directly instantiates a `LinearLayout` container (`ViewGroup`) via Java code (`L2-Q26`).
- **`layout.setOrientation(LinearLayout.VERTICAL);`**  
  Sets orientation along the vertical axis. Children are positioned strictly from top to bottom.
- **`layout.setLayoutParams(new LinearLayout.LayoutParams(...));`**  
  `LayoutParams` tell the parent container how to measure and position this view. `MATCH_PARENT` instructs the view to fill all available width and height inside the parent container (`L3-Q03`).
- **`layout.setGravity(Gravity.CENTER_HORIZONTAL);`**  
  Aligns all child views horizontally along the center axis of the layout.
- **`dayTextView.setText("Thursday");`**  
  Imperatively sets the character sequence displayed inside the `TextView`.
- **`weatherIcon.setImageResource(R.drawable.weather_sunny);`**  
  Resolves the 32-bit hex resource ID generated by AAPT (`R.drawable.weather_sunny`) and binds the bitmap to the `ImageView`.
- **`res/drawable-hdpi` Asset Naming Rules (`L2-Q30`):**  
  All files placed in resource directories must contain **only lowercase letters (`a-z`), digits (`0-9`), and underscores (`_`)**, and must **never start with a digit** (e.g., `1_sunny.png` causes AAPT build errors; `weather_sunny.png` is valid).
- **`layout.addView(dayTextView);` and `layout.addView(weatherIcon);`**  
  Appends children to the `ViewGroup` child array. Order determines rendering sequence: `dayTextView` appears first (top), and `weatherIcon` appears immediately below it.

### 7.3 Exhaustive Line-by-Line Breakdown:
- **`inflater.inflate(R.layout.fragment_forecast, container, false);`**  
  **CRITICAL EXAM METHOD (`L3-Q05`).**
  - First argument: Layout resource ID to inflate.
  - Second argument: Target `ViewGroup` container, providing `LayoutParams` so root view dimensions are accurately calculated.
  - Third argument (`attachToRoot = false`): **Mandatory.** When false, the layout is inflated and returned to the caller. The `FragmentManager` will handle attaching it to the activity at the appropriate lifecycle step. If set to `true`, the view is attached immediately, and the caller crashes with an `IllegalStateException: The specified child already has a parent`.
- **`android:layout_width="match_parent"` vs. `wrap_content` (`L3-Q03`):**  
  Every XML view requires these two attributes. `match_parent` expands to fill the container; `wrap_content` sizes the view strictly to fit its content.
- **`android:scaleType="fitCenter"` (`L2-Q28`):**  
  Scales the image uniformly preserving the aspect ratio so that the entire image fits within the 120dp x 120dp frame, centered inside the view.
- **`android:textSize="22sp"` (`L3-Q22`):**  
  Font dimensions must always use Scale-independent Pixels (`sp`), which scale dynamically according to user accessibility settings in system preferences. Density-independent Pixels (`dp`) are reserved for layout widths, heights, margins, and padding.

### 7.4 LinearLayout Weight Formula Derivation (Lecture 4, Slide 21–23 & MCQ `L3-Q07`, `L3-Q08`)
In horizontal LinearLayouts where children declare `android:layout_weight`, Android resolves view widths in three discrete calculation passes:

```text
Step 1: Calculate Total Unallocated Space:
Remaining_Space = Width_parent - Sum(base_fixed_widths)

Step 2: Calculate Sum of All Weights:
Total_Weight = Sum(weight_i)

Step 3: Allocate Proportional Extra Width to Child i:
Width_final_i = base_width_i + (weight_i / Total_Weight) * Remaining_Space
```

#### Example Derivation (Slide 23 Exercise):
- Container Width: `720px`
- Button 1: `width="0px"`, `weight="1"`
- Button 2: `width="100px"`, no weight (`weight="0"`)
- Button 3: `width="0px"`, `weight="1"`

```text
Fixed Width = 100px
Remaining Space = 720px - 100px = 620px
Total Weight = 1 + 0 + 1 = 2

Button 1 Width = 0px + (1 / 2) * 620px = 310px
Button 2 Width = 100px (Fixed)
Button 3 Width = 0px + (1 / 2) * 620px = 310px
```

### 12.3 Exhaustive Line-by-Line Breakdown:
- **Extra 1-Pixel Perimeter Border (`L3-Q26`):** A 9-Patch image is a standard PNG surrounded by an extra 1-pixel-wide transparent perimeter frame containing solid black guide pixels (`#000000`).
- **Top Edge (Black pixels):** Defines the **horizontal stretchable columns**. When the view widens, only the pixel columns directly under these black marks are stretched. Corners remain crisp.
- **Left Edge (Black pixels):** Defines the **vertical stretchable rows**. When the view lengthens, only pixel rows directly aligned with these marks are stretched.
- **Bottom Edge (Black pixels):** Defines the **horizontal content padding area**.
- **Right Edge (Black pixels):** Defines the **vertical content padding area**.
- **Strict Transparency Requirement (`L3-Q28`):** Any perimeter guide pixel that is not marking a stretch or padding zone must be **100% transparent**. A non-transparent border pixel will cause an AAPT compile error (`ERROR: 9-patch image malformed`).

### 13.2 File Streaming & Playback in `WeatherActivity.java`
```java
package vn.edu.usth.weather;

import android.media.MediaPlayer;
import android.os.Bundle;
import android.util.Log;
import android.widget.Toast;
import androidx.appcompat.app.AppCompatActivity;
import java.io.File;
import java.io.FileOutputStream;
import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;

public class WeatherActivity extends AppCompatActivity {
  private static final String TAG = "WeatherActivity";
  private MediaPlayer mediaPlayer;

  @Override
  protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    setContentView(R.layout.activity_weather);

    // Extract MP3 from res/raw/ to app-specific external storage and play
    extractAndPlayAudio();
  }

  private void extractAndPlayAudio() {
    File targetDir = getExternalFilesDir(null);
    if (targetDir == null) {
      Log.e(TAG, "External storage unavailable.");
      return;
    }

    File outputFile = new File(targetDir, "weather_ambient.mp3");

    // Copy stream using try-with-resources (checked IOException handling: L1-Q26)
    try (InputStream is = getResources().openRawResource(R.raw.weather_sound);
         OutputStream os = new FileOutputStream(outputFile)) {

      byte[] buffer = new byte[4096];
      int length;
      while ((length = is.read(buffer)) > 0) {
        os.write(buffer, 0, length);
      }
      os.flush();

      Log.i(TAG, "File extracted successfully: " + outputFile.getAbsolutePath());

      // Initialize MediaPlayer with the extracted file
      mediaPlayer = new MediaPlayer();
      mediaPlayer.setDataSource(outputFile.getAbsolutePath());
      mediaPlayer.prepare();
      mediaPlayer.start();

    } catch (IOException e) {
      Log.e(TAG, "Failed to extract or play audio", e);
      Toast.makeText(this, "Audio extraction error", Toast.LENGTH_SHORT).show();
    }
  }

  @Override
  protected void onPause() {
    super.onPause();
    // Pause audio playback when screen turns off or activity loses focus
    if (mediaPlayer != null && mediaPlayer.isPlaying()) {
      mediaPlayer.pause();
    }
  }

  @Override
  protected void onDestroy() {
    super.onDestroy();
    // Release native media player resources to prevent memory leaks (L2-Q18)
    if (mediaPlayer != null) {
      mediaPlayer.stop();
      mediaPlayer.release();
      mediaPlayer = null;
    }
  }
}
```

### 13.3 Exhaustive Line-by-Line Breakdown:
- **`res/raw/` vs. `assets/` Architectural Differences (`L3-Q31`, `L3-Q32`):**
  - **`res/raw/`:** Files are indexed by AAPT into `R.raw.<filename>`. They must follow strict resource naming rules (lowercase, digits, underscores) and do **not** support subdirectories. Accessed via `getResources().openRawResource(R.raw.id)`.
  - **`assets/`:** Arbitrary filesystem directory bundled into the APK. Allows subdirectories (e.g. `assets/audio/weather.mp3`), mixed cases, and spaces. Accessed via `getAssets().open("path")`. Does not generate IDs in `R.java`.
- **`getExternalFilesDir(null)`:** Returns an app-specific directory on external storage (e.g. `/sdcard/Android/data/vn.edu.usth.weather/files`). On modern Android versions, this directory requires **no runtime permissions**.
- **`byte[] buffer = new byte[4096];`:** Allocates a 4KB chunk in memory. Reading in chunks avoids loading the entire MP3 into memory at once, preventing `OutOfMemoryError` (`L2-Q10`).
- **`mediaPlayer.release()` inside `onDestroy()` (`L2-Q18`):**  
  `MediaPlayer` allocates underlying native C/C++ decoding engines (Stagefright / OpenMAX). Calling `release()` reclaims these low-level system resources.
